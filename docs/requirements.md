# 要件定義書 — 英語リスニングアプリ

## 1. 概要

英語のリスニング学習を目的とした Web アプリケーション。読み上げられる英文を聞き、英文と日本語訳を確認しながら学習する。2 つの学習モード（日常会話 / AWS 技術カンファレンス）を提供する。

- 公開 URL: `https://listening.example.com`
- 静的 Web ホスティング（S3 + CloudFront + Route53 + ACM）で HTTPS 配信
- 音声は Amazon Polly で **事前生成** した mp3 を配信（実行時に AWS API を呼ばない）

## 2. 用語

| 用語 | 意味 |
|---|---|
| 日常会話モード | 中学英語レベルから徐々に難易度が上がる日常会話の問題群 |
| カンファレンスモード | AWS の技術カンファレンス（re:Invent 等）のセッション聴講に備える問題群。内容は AWS に限定 |
| 問題 (item) | 1 つの英文 + その日本語訳 + 対応する音声 mp3 のセット |

## 3. 機能要件

### 3.1 学習モード
- FR-1: 日常会話モードとカンファレンスモードの 2 つを切り替えられること（画面上部のタブ）。
- FR-2: 各モードは初期リリースで **20 問** を用意すること。
- FR-3: 日常会話モードは中学英語レベルから始まり、問題が進むにつれ徐々に難易度が上がること。
- FR-4: カンファレンスモードの内容は AWS に関するトピックに限定すること。

### 3.2 画面・表示
- FR-5: 1 画面構成とし、以下を表示すること（手書きラフに準拠）。
  - 上部: モード切替タブ（MODE1 = 日常会話 / MODE2 = カンファレンス）
  - 中段上: 英文表示エリア（EN）
  - 中段下: 日本語訳表示エリア（JP）
  - 下部: 音声コントローラー（再生 / 一時停止、シークバー、再生速度切替）
  - 最下部: 前の問題へ（prev） / 次の問題へ（next）
- FR-6: 再生速度は `x0.75` / `x1.0` / `x1.5` を UI で切り替えられること（ブラウザの再生速度）。

### 3.3 音声
- FR-7: 音声は Amazon Polly（Neural、米国英語）で事前生成した mp3 を再生すること。
- FR-8: ボイスは Joanna（女性）と Matthew（男性）を混在させること（実現可能な場合。必須ではない）。
- FR-9: 日常会話モードは、問題の進行に応じて読み上げ速度を段階的に速くし、難易度の 1 要素とすること（Polly 生成時の `prosody rate`）。この「生成時の速度」は UI の再生速度切替とは独立。

### 3.4 スコープ外（初期リリース）
- 学習履歴・進捗の記録は行わない。
- ユーザー認証は行わない。
- SNS 連携は行わない。

> ただし、将来的に「学習履歴モード」「SNS 連携」等を追加する可能性があるため、DB・認証・API を後付けしやすい構成とする（非機能要件 NFR-4 参照）。

## 4. 非機能要件

- NFR-1: HTTPS でのアクセス（ACM 証明書、CloudFront 経由）。
- NFR-2: 独自ドメイン `listening.example.com` で配信。
- NFR-3: ランタイムでの AWS API 呼び出しを行わず、静的配信のみで完結（低コスト・低運用）。
- NFR-4: 拡張性 — 将来の学習履歴 / 認証 / SNS 連携のため、バックエンド（API Gateway + Lambda + DynamoDB + Cognito 等）を後付けできるよう、フロントは SPA（React + Vite）とし、IaC はスタックを分割する。
- NFR-5: レスポンシブ対応（スマートフォン縦画面を主要ターゲットとしつつ PC でも崩れない）。
- NFR-6: インフラは CloudFormation / SAM でコード管理する。

## 5. AWS アカウント・DNS 構成

| 項目 | 値 |
|---|---|
| アプリ構築先アカウント | `<APP_ACCOUNT_ID>`（既存で別プロダクトの本番も稼働。リソース衝突に留意） |
| 親ドメイン `example.com` の Route53 パブリックホストゾーン | `<PARENT_ACCOUNT_ID>` |

### DNS 方針（NS 委譲）
- アプリ側アカウント `<APP_ACCOUNT_ID>` に `listening.example.com` のパブリックホストゾーンを作成する。
- 親ゾーン（`<PARENT_ACCOUNT_ID>`）に `listening.example.com` の **NS レコード**を 1 回登録し、サブドメインの運用をアプリ側アカウントに委譲する。
- これにより、ACM 証明書の DNS 検証レコード、CloudFront へのエイリアスレコードはすべてアプリ側アカウント `<APP_ACCOUNT_ID>` で完結する。
- 親ゾーン側（`<PARENT_ACCOUNT_ID>`）での作業は **NS レコードの初回登録のみ**。

### 作業時の認証
- 各アカウントでの作業が必要になった時点で、AWS CLI の一時認証情報を都度取得して作業を依頼する。
- ACM 証明書は CloudFront 用のため **us-east-1** で発行する。

## 6. 制約・留意事項

- アプリ側アカウント `<APP_ACCOUNT_ID>` には別プロダクトの本番リソースが存在するため、リソース名は本アプリ専用のプレフィックス（例: `listening-app-`）で明確に分離する。
- 初期リリースはコンテンツ 40 問（20 問 × 2 モード）。英文・和訳はプロジェクト側で新規作成する。

## 7. 受け入れ基準

- `https://listening.example.com` に HTTPS でアクセスでき、画面が表示される。
- MODE1 / MODE2 を切り替えられる。
- 各モードで 20 問を prev/next で行き来でき、各問題の英文・和訳が表示される。
- 各問題の音声が再生・一時停止でき、シークとx0.75/x1.0/x1.5 の速度切替ができる。
- 日常会話モードで、問題が進むにつれ生成音声の読み上げ速度が段階的に上がっている。
